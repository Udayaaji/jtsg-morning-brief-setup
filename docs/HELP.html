JTSG Morning Brief

Everyday guide. Installation is already done; this covers using it.

What happens every morning

The brief is generated Monday to Saturday. The scheduled time is 06:40, and it also starts when you sign in to Windows, so on a day you sign in earlier it is produced then instead. Sundays are skipped.

A run takes 10 to 30 minutes. Keep the lid open while it works; the computer will not go to sleep on its own during a run. If the machine was off at 06:40, the run is picked up the next time you sign in.

What arrives in the delivery folder

Four files a day, in the folder you chose at install (by default Documents\JTSG Morning Brief). You can move or delete them freely; nothing depends on them staying there.

FileWhat it is
Morning_Brief_JTSG_<date>.pdf The brief itself. Review it before circulating it.
Morning_Brief_Status_<date>.md What happened this morning, and anything you need to know. Start here on a day something looks off.
sources_<date>.md Every web page the research actually opened, so any figure in the brief can be traced back.
social_<date>.md Short posts drawn from the day's brief, ready to adapt.
A PDF stamped "UNVERIFIED DRAFT, NOT FOR CIRCULATION" is never a deliverable. Every brief passes a chain of automatic checks before it is released, and the watermark means one of them was skipped. If you ever see it, do not circulate the brief; send us the status report instead.

Reading the status report

The top of the file is written for you and is usually four lines. It names what happened and what, if anything, you need to do. Everything under Details for support is for us: you never need to read it, but when you report a problem, forward the whole file rather than a description of it.

Market figures

The brief carries eleven market figures. If any of them is not in today's brief, the status report names it rather than letting it disappear quietly, and tells you which kind of gap it is:

  • "not a payload row, so a gap here can be routine" means the figure comes from a dated news source rather than the market data feed. Some mornings no such source has published yet. This is normal and needs nothing from you.
  • "a payload row, so this should not be missing" means the figure was available and still did not reach the brief. If you see this on two days running, forward the status report to us.

On a normal morning this section does not appear at all, which means every figure is present.

Notifications, and what each one means

NotificationWhat to do
Morning Brief ready for review Click it to open the delivery folder. Review the PDF, then circulate it when you are satisfied.
Morning Brief not produced today Open the status report in the delivery folder. Its first lines say what happened. Often nothing is needed from you and tomorrow's run continues normally. If it asks you to forward the file, send it to us.
Sign in to continue The stored Claude sign-in has expired. Start Menu, JTSG Morning Brief, Sign in to Claude. This is routine, not a fault.
Morning Brief is not set up correctly Click it to open the logs folder, then forward the launcher log to us.

Start Menu shortcuts

Under JTSG Morning Brief:

  • Morning Brief folder opens where the briefs are saved.
  • Run Morning Brief now starts a run immediately, for a day you want it earlier or want to retry after a problem.
  • Sign in to Claude renews the sign-in.
  • Morning Brief schedule pauses, resumes or retimes the morning run without opening Task Scheduler.
  • Help opens this page.

Pausing or retiming the morning run

Open Morning Brief schedule. It shows whether the run is currently enabled and at what time, then offers a numbered menu. Use it to pause the run while you are away and resume it when you return, or to move it earlier or later.

It changes the schedule only. It cannot alter the brief or skip any of the checks the brief passes before release.

About the Claude sign-in

The single sign-in you did at the end of installation is the connection. It is stored on this computer and every morning's run uses it. The cost of generating the brief sits on the firm's Claude subscription; nothing is billed by us.

If a morning is missed because the subscription's usage limit was reached, the status report says so plainly. The limit resets on its own and the next scheduled start or Windows sign-in tries again.

If something looks wrong

Send us the day's Morning_Brief_Status_<date>.md. It is designed so that one forwarded file is enough for us to work from, which saves a round of questions. If there is no status report at all for that day, send the launcher log from the logs folder instead.

Removing it

Settings, Apps, JTSG Morning Brief, Uninstall. Your delivery folder and every brief in it are left in place. Claude Code itself stays installed; remove it separately if you want it gone.
